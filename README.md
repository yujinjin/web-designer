### 将字符串解析成可执行JavasCript代码

- 说明：可以使用Function构造函数来动态创建函数并执行。new Function(arg1, arg2, ..., argN, function_body)构造函数接受任意数量的参数，最后一个参数为函数体字符串，其参数和函数体都以字符串形式传入。例如：

```js
const codeString = "var sum ; sum = x+y;return sum;";
const myFunction = new Function("x", "y", codeString);
myFunction(2, 3);
```

- 需要注意的是，new Function中的代码执行时的作用域为全局作用域，不论它在哪个地方被调用，它访问的都是全局变量和内部定义的参数变量，它是无法访问函数内的局部变量。
- 使用Function构造函数同样具有一定的安全风险，因为它可以动态创建和执行任意的JavaScript代码。因此，在使用Function构造函数时，需要谨慎处理传入的参数和函数体字符串，避免执行恶意代码。

### 待优化事项

1. 增加布局型组件
   关键词：
   /opsx:explore
   当前项目的组件库还缺少一些布局类型的组件，帮我增加布局类型的行容器组件，并实现它，具体要求如下：
    1. 行容器组件用于将多个组件平铺排列在一起，建议使用el-row组件。
    2. 普通组件拖入行容器内部，其容器内部组件可拖拽排序和删除（不用复制）。
    3. 行容器组件的占用宽度可以通过配置栅格数的方式来实现，默认不做栅格配置，每增加一个组件时用平均值（默认行容器是24个栅格宽度），如果使用配置栅格数的方式，每个组件的占用栅格数不能超过24个，组合超过24个栅格数时，会自动换行。栅格数据的配置一定要定义在行容器组件里，不要定义在普通组件里。
    4. 行容器组件的最多支持拖拽进来 6 个组件，不做栅格配置时每个组件栅格自动平局分，比如：2个组件每个占用12个栅格宽度，5个组件【5，5，5，5，4】。
    5. 行容器的组件数据结构有2种设计方式：
       一种是单独分开：考虑到行容器组件只是用于排版组件布局的，并不算是真正意义的组件，所有的组件都在widgets下面，包括行容器里的组件；行容器在WidgetFormData里单独定义个属性数组，来存放当前表单下的所有含容器数据；widgets下面的普通的组件不要有行容器的数据，只在行容器里定义它引用的组件数据；这样就不会破坏现有的组件数据结构；行容器组件只能算是一个引用组件的关系，可以利用其设置开始组件位置的属性和组件占用栅格数的列表（Array<number>）来知道行容器里的组件数据。缺点是渲染的时候得重新组合起来，拖拽、移动都要重新处理一遍；

        另一种是直接作为子组件：行容器组件放在widgets里面，其拖拽进来的子组件放在行容器组件的widgets属性里；缺点就是数据结构有重大变化里面的拖拽、移动都要重新计算；这里可以提供设计方案：
        1. 定义一个计算属性，来计算当前表单下的所有组件，其数据验证、渲染的表单数据、提交的表单数据等用到表单相关的数据都用这个计算属性来处理；
        2. 组件的复制、排序、新增等操作方法可以通过增加一个可传参数来判断是否是在父级容器（行容器组件）里操作的。删除方法应该不需要，因为可以遍历子项数据来删除。

    注意：布局类的组件有个问题要考虑到其他组件可以拖拽到布局组件里，但是布局组件本身不能拖拽到其他组件里，而且布局类的组件内部多个其他组件还可以拖拽排序，为防止多重嵌套所以要限制布局类型的组件拖拽进来
